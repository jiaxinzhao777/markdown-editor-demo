# data-platform-2.0-demo 编辑器对比与选型建议

当前场景是采集标准的编辑与发布：在弹窗中修改标题、列表、表格、引用等内容，填写变更说明，再发布新版本。现有界面采用“Markdown 源码 + 预览”，选型主要看两点：业务人员改文档是否方便，以及能否继续沿用 Markdown 内容和现有发布流程。

## 1. 优缺点对比

以下对比基于本次 Demo 的接入方式。

| 方案 | 优点 | 缺点及对当前业务的影响 |
| --- | --- | --- |
| **MDXEditor** | 直接编辑排版后的文档，标题、列表、表格都有操作入口；支持切回源码和查看差异；仍可读写 Markdown。 | 保存时可能调整空行、列表符号等格式，产生额外的源码差异；接入前要确认历史标准文档不会丢内容。 |
| **uiw / React MD Editor** | 与现有“源码 + 预览”界面最接近；自带格式工具栏，接入现有表单的改动较小。 | 仍需要看懂 Markdown；修改复杂列表和表格时，业务人员还是要处理源码。 |
| **Milkdown / Crepe** | 可视化编辑，提供斜杠菜单、块操作和表格交互，适合连续编写长文档。 | 定制工具栏和行为需要熟悉其插件体系；对当前标准编辑弹窗来说，接入和后续维护工作更多。 |
| **Vditor** | 中文工具栏，可切换源码、即时渲染和所见即所得模式，能照顾不同使用习惯。 | 需要额外处理资源部署和 React 中的实例管理；三种模式也增加了界面配置和测试工作。 |
| **TOAST UI Editor** | Markdown 与可视化双模式，表格和预览功能齐全，能覆盖常见标准文档。 | 当前 Demo 通过原生 JS 实例接入，需要自行处理弹窗反复打开、内容更新和销毁；切换模式后的内容也需核对。 |
| **md-editor-rt** | 中文工具栏、目录、预览较完整，适合较长的 Markdown 文档。 | 仍以源码编辑为主；默认功能较多，放进现有弹窗需要精简工具栏。 |
| **CodeMirror 6** | 直接编辑原始文本，有高亮、搜索和撤销；不会因为富文本转换而改写未编辑的语法。 | 只是源码编辑基础，预览和格式工具栏需要自建；对不熟悉 Markdown 的人员帮助有限。 |
| **EasyMDE** | 基础工具栏和预览齐全，适合简单的 Markdown 输入。 | 表格仍主要通过源码修改；需要自行封装 React 生命周期，相比 uiw，对当前场景没有明显收益。 |
| **Tiptap + Markdown** | 扩展能力强，可以增加业务卡片、自定义节点和复杂编辑操作。 | 工具栏和业务交互需要自己建设，Markdown 转换也要单独验证；当前只是编辑标准文档，投入偏大。 |
| **BlockNote** | 块拖拽、斜杠菜单和浮动工具栏齐全，适合搭建类似 Notion 的文档界面。 | Markdown 导入导出有损，完整保留块内容更适合使用 JSON 存储；与当前 Markdown 文档和历史版本的使用方式不太匹配。 |

## 2. 选型建议与理由

### 首选 MDXEditor：让业务人员直接修改文档

建议用 MDXEditor 替换弹窗中的正文编辑区域，默认显示可视化编辑，保留切换源码的入口。“变更说明”和“发布新版本”继续放在现有位置，发布时读取编辑器输出的 Markdown，沿用原有流程。

选择它主要有三个理由：

- **更适合修改采集标准。** 调整章节、增删规则、修改表格，可以直接操作文档，减少在源码和预览之间来回核对。
- **与现有内容格式衔接较直接。** 可以载入已有 Markdown，再输出 Markdown，无需为了更换编辑器同时改成块 JSON 存储。
- **当前需要的功能已经接入 Demo。** 标题、列表、引用、链接、表格、源码和差异视图都有，不需要像 Tiptap 那样从基础能力开始搭建。

接入前，先拿几份真实历史标准做一次“打开 → 修改 → 发布 → 重开”，重点检查表格、嵌套列表和引用。MDXEditor 可能调整源码排版；如果业务要求未修改的 Markdown 必须逐字保留，就不适合选择这类可视化编辑器。

### 备选 uiw：保留现有操作方式，优先减少改动

如果这次只想给现有源码输入框补上加粗、标题、列表等工具栏，或者使用者已经习惯 Markdown，就选 uiw。它与截图中的双栏界面最接近，容易接入原来的弹窗和表单。

代价也很明确：它改善的是源码编辑工具，无法解决业务人员不熟悉 Markdown、表格源码难修改的问题。

### 其他方案暂不作为首选

Milkdown、Vditor 和 TOAST UI 也能完成标准文档编辑，但对当前需求，没有足够明确的收益来抵消额外的适配工作。md-editor-rt、CodeMirror 和 EasyMDE 仍以源码编辑为主，当前先比较 uiw 即可。Tiptap 和 BlockNote 更适合后续明确需要业务卡片或块文档时再考虑。
